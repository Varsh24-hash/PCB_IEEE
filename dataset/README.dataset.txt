
# FGA-YOLOV12 PCB Detection Dataset

## 📌 Dataset Overview

This dataset contains **3,800 high-resolution images** of the publicly available Kaggle dataset (PKU-Market) and custom images generated synthetically on real PCB images using a strong image generation pipeline.

The data is provided in a **flat directory structure** (all images in one folder, all labels in another) to facilitate **K-Fold Cross-Validation**. This structure allows training scripts to dynamically split the data into training and validation sets (e.g., 80/20 split for 5-fold) for robust performance evaluation, as detailed in the accompanying research paper.

## 📂 Directory Structure

The dataset is organized as a single pool of data pairs:

```
FGA-YOLOV12-PCB-Dataset/
├── images/          (Contains all 3,800 image files)
├── labels/          (Contains all 3,800 YOLO format .txt files)
└── README.md        (This file)

```

## 📊 Dataset Specifications

* **Total Samples:** 3,800 Image-Label Pairs
* **Intended Use:** 5-Fold Cross-Validation (Script-based splitting)
* **Defect Scale:** Microscopic (Small objects relative to image size)
* **Background Complexity:** High (Complex circuitry patterns)

## 🏷️ Defect Classes

The dataset includes annotations for the following defect types.
*(Ensure your `classes.txt` or `data.yaml` follows this order)*

| Class ID | Class Name | Description |
| --- | --- | --- |
| `0` | **Open** | Discontinuity in the circuit path. |
| `1` | **Short** | Unintended connection between two copper traces. |
| `2` | **Mousebite** | Erosion of material along trace edges. |
| `3` | **Spur** | Protrusion of copper from a trace. |
| `4` | **Missing-hole** | Small holes in the copper pads/traces. |
| `5` | **Copper** | Residual copper on the substrate. |

## 🚀 Usage Guide

Since this dataset is not pre-split into `train/val`, you must define the split logic in your training script.

**Example: 5-Fold Cross-Validation Workflow**

1. **Load:** The script reads all files from `images/`.
2. **Shuffle & Split:** The script randomly shuffles indices and splits them into 5 folds.
3. **Iterate:** For each fold, 80% of data (3,040 images) is used for training, and 20% (760 images) for validation.

**Sample `data.yaml` Configuration:**
If using a custom script to generate absolute paths, your yaml might look like this:

```yaml
path: /content/FGA-YOLOV12-Dataset  # Root dataset directory
train: images  # Path relative to root (or absolute path list generated by script)
val: images    # Path relative to root (or absolute path list generated by script)

names:
  0: Open
  1: Short
  2: Mousebite
  3: Spur
  4: Missing-hole
  5: Copper

```
